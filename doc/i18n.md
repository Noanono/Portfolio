# Languages (EN / FR)

The site exists in English (default, `/`) and French (`/fr`). There is no
i18n dependency: a small typed dictionary is enough for two languages.

| English            | French                |
| ------------------ | --------------------- |
| `/`                | `/fr`                 |
| `/projects`        | `/fr/projects`        |
| `/projects/<slug>` | `/fr/projects/<slug>` |
| `/about`           | `/fr/about`           |

The `/bde/` embedded site is a separate static build and stays in French.

## Where the texts live

- `app/i18n/messages.ts`: interface and page texts (navigation, home,
  projects labels, about page). One `en` and one `fr` object, both typed
  with `Messages`.
- `app/data/projects.ts`: project texts. Each translatable field is a
  `{ en, fr }` pair.
- `app/i18n/locale.ts`: locale list, path helpers (`localeFromPath`,
  `localizedPath`) and `absoluteUrl` for SEO links.

Because both dictionaries share one type, a missing translation is a
TypeScript error, so `npm run typecheck` and `npm run generate` fail
instead of shipping a half-translated page.

## Using it in a component

```vue
<script setup lang="ts">
const { t, locale, localePath } = useLocale()
</script>

<template>
  <h1>{{ t.home.title }}</h1>
  <NuxtLink :to="localePath('/projects')">{{ t.site.nav.projects }}</NuxtLink>
</template>
```

Always build internal links with `localePath()`, otherwise a visitor on
`/fr` lands back on the English page.

## How routing works

Each page declares the French URL as an alias:

```ts
definePageMeta({ alias: ['/fr/about'] })
```

`useLocale()` derives the language from `useRoute().path`, so the same
page component renders both versions.

### Language switch is a full page load

The switch in the header is a `NuxtLink` with `external`. This is
deliberate: vue-router treats `/about` and `/fr/about` as the same route
record and ignores navigation between aliases ("redundant navigation"),
so a client-side link would do nothing. A full load also guarantees the
prerendered `<html lang>` and `hreflang` tags match the page.

## CV

The CV is a PDF in each language, in `public/cv/`:

- `Noah-Soler-CV-en.pdf`
- `Noah-Soler-CV-fr.pdf`

`useLocale()` returns `cvHref`, the file for the current language, so the
download button on the home page and the footer link follow the language of
the page. To update the CV, replace both files and keep the names.

## SEO

`app/layouts/default.vue` sets `<html lang>` and `hreflang` alternates
(`en`, `fr`, `x-default`). Alternate URLs end with a slash to match what
Cloudflare serves after its automatic trailing-slash redirect.

## Adding a page

1. Add the page with `definePageMeta({ alias: ['/fr/<path>'] })`.
2. Add its texts to both `en` and `fr` in `messages.ts` (extend the
   `Messages` interface first).
3. Use `useLocale()` and `localePath()` in the page.
