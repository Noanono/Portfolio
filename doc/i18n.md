# Languages

The site is available in English (United States) and French (France), and adding
a language is meant to take nothing more than its texts.

## URLs

Every language has its own sub-directory, the default one included, named after
its **language and region** (`en-US`, `fr-FR`, `fr-BE`, `es-MX`…). The region is
required, as hreflang expects it. The URL is the code in lower case:

| Page            | `en-US`                   | `fr-FR`                   |
| --------------- | ------------------------- | ------------------------- |
| Home            | `/en-us/`                 | `/fr-fr/`                 |
| Projects        | `/en-us/projects/`        | `/fr-fr/projects/`        |
| One project     | `/en-us/projects/<slug>/` | `/fr-fr/projects/<slug>/` |
| About           | `/en-us/about/`           | `/fr-fr/about/`           |

The root `/` has no content. It sends each visitor to the language of their
browser (English when that language is not available) and lists the languages
for browsers without JavaScript. It is `noindex`, so search engines index the
language versions only.

The browser's language is matched exactly first (`fr-BE`). Otherwise the same
language is used: `fr-CA` or `fr` get `fr-FR` if it exists, else the first
French version. `en-AU` gets `en-US`.

The old URLs (`/about`, `/projects/...`, `/en/...`, `/fr/...`) redirect with a
301 to the new ones (`public/_redirects`).

The `/bde/` site is a separate static build and stays in French.

## Add a language

1. Copy `app/i18n/locales/en-us.ts` to `app/i18n/locales/<language>-<region>.ts`
   in lower case, for example `de-de.ts`, `fr-be.ts` or `es-mx.ts`. Any other
   name stops the build with an explanation.
2. Translate it: `name` (the language's own name, shown in the switch; add the
   country when two versions share a language, like "Français (Belgique)"),
   `messages` and `projects`.
3. Optional: put the CV in `public/cv/` and set `cv`. Without it, the
   English CV is offered.

That is all. These come from the list of files, with nothing else to edit:

- the `/<language>-<region>/` routes (any other prefix is a 404) and their
  prerendering
- `<html lang>`, the `canonical` and `hreflang` tags of every page
  (`hreflang="fr-BE"`), `x-default`
- the language switch in the header
- `sitemap.xml`, with the alternates of each page
- the redirection from `/` for visitors whose browser speaks that language

TypeScript fails `npm run typecheck` and the build if a file misses a message or
a project text, so a language cannot ship half translated.

The default language is set in `app/i18n/config.ts`.

## Where the texts are

Each file in `app/i18n/locales` holds everything translatable for one language:

- `messages`: navigation, footer and the text of each page
- `projects`: title, summary, description and labels of each project, by `slug`

What does not depend on the language (links, which projects are featured, the
embedded site) is in `app/data/projects.ts`.

## Using it in a component

```vue
<script setup lang="ts">
const { t, locale, localePath } = useLocale()
</script>

<template>
  <h1>{{ t.home.title }}</h1>
  <NuxtLink :to="localePath('/projects')">{{ t.site.projects }}</NuxtLink>
</template>
```

Build internal links with `localePath()`, otherwise a visitor on `/fr-fr/` lands
on the English page. Links come out with their final trailing slash, so none of
them goes through a redirect.

## Add a page

Create it under `app/pages/[lang]/` and read its texts with `useLocale()`. Add
the texts to the `messages` of every language (extend `Messages` in
`app/i18n/types.ts` first). Routing, hreflang and the sitemap follow.

## SEO rules

The site follows the rules of
[this guide](https://seaudit.fr/fr/blog/hreflang-seo-multilingue-international-2026):

- one sub-directory per language and region
- `hreflang` codes are language-region: `en-US`, `fr-FR`, `fr-BE`
- each page lists itself and all its translations with `hreflang`, plus
  `x-default` (the page in the default language)
- reciprocity: if page A points to page B, B points to A
- absolute URLs, with the same trailing slash as the `canonical`, never a URL
  that redirects
- the `canonical` of a page is the page itself, in its own language
- `<head>` and `sitemap.xml` say the same thing; `robots.txt` declares the
  sitemap and blocks no language

`npm run check:seo` checks all of this on the generated site. It runs in CI
after the build, and fails with the list of problems.

## Language switch

The switch in the header links to the same page in each other language, and
works without reloading the page (the language is a parameter of the route).
